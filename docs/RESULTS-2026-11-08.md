## 2. 为什么之前编不出来（三个独立的死结）

1. **candidate 自举死锁**：设备仓库的归档脚本（`build-sheng-platform-power.py`、`build-native-legacy-display.py`、`build-native-aes-bindings.py`、`build-native-hid-input.py`）都要一份 `build/native-prelink/native-owner-ufs-cpu-desktop-*-candidate.macho`——那是作者机器上的历史产物，仓库里没有、也没有任何 recipe 能产出它。作者的 `build-legacy-stub.py` 里写着绕法（Stage A：先链一个没有 storage/display 的内核，拿它的 prelink 产物当 candidate）。
2. **显示驱动生成头缺声明**：`scripts/build-native-legacy-display.py` 生成的 `OriginalLegacyFramebufferABI.h` 少了 `OriginalLegacyStateRequest`、`kLegacyVsyncClients`、`kRequestRect0/1/Masks/Options/Dims/Surfaces`、`NATIVE_LEGACY_LEAVES` 宏和 slot 354 的 `applyStateRequest`；上游 `UniXNU/UniXNU-sheng` 的同名生成器里有，搬过来 73 个编译错立刻降到 1 个。
3. **上游脚本里三处陈旧路径**：`build-xnu-4k-baseline.sh` 写死 `build/sheng-ufs/libShengUfs.a`、`build/ram-block/libRamBlock.a`、`build/ram-block/NativeRamBlock.o`，而 recipe 实际产出 `build/native-ufs/libNativeUfs.a`、`build/native-ram-block/libNativeRamBlock.a|.o`。

## 3. 我们做了什么（全部在 CI 里，脚本都进仓库）

- **`chipppppppps/fuxi-t50` 的 `t50-kernel.yml`**（workflow 410274358，23 步，`workflow_dispatch` 输入 `display=stub|real`）
  - 从 artifact `13571916750`（Stage A 内核）取 candidate，塞进 `out/fuxi/tree/build/{xnu-prelink,native-prelink}`；
  - 用 `Display=real` 时保留显示归档，同时补 `OriginalLegacyStateRequest` 等 6 行声明 + slot 354；
  - 摘掉 `build-adreno740-kits.py`、`build-adreno740-accelerator.py`、`build-arm-driver.py Adreno740`（树的 XNU 头只有 `task_get_game_mode`，驱动要 `task_get_gpu_role`/`PRIO_DARWIN_GPU_*`），并给 Adreno 归档块加存在性守卫；
  - 把 `GpuPowerProbe` 从显示归档里摘掉（它引用 Adreno 的 C++ 接口）；
  - 修三处陈旧路径；
  - 自愈桩循环：抓 `"...", referenced from:` 生成 arm64 桩、重链，最多 4 轮（注意符号名本身已带前导下划线，别再补 `_`）；
  - 桩归档通过 `stage-a/link.txt` + 手工注入 `-force_load` 进 `LD_KERNEL_ARCHIVES`（`CONFIG_XNU_EXTRA_LD_ARCHIVES` 不会被驱动导出）。
- **`t50-pack.yml`**（workflow 410396642，19 步）
  - 装 `llvm`、`lld`、`dtc`（`llvm-nm`/`ld.lld`/`fdtget` 都在里面）；
  - 把 entry probe 的 padding 判定改成容忍 nop 填充与非 4 字节对齐的尾巴（本内核的 cave 是 `1f2003d5`，不是零）；
  - `fuxi.dsc` 删掉 `AdvancedLogViewLib` 映射、`FuxiUfsLogDxe`/`FuxiUefiLogDxe` 两个组件，`Include/DXE.inc` 删掉对应两行 `INF`（这个库只存在于作者机器上，UniXNU 组织里全站 0 命中）；
  - `git submodule update --init --depth 1 -- Binaries`（`nuwa` 的 `EnvDxe` 二进制来自 Device-Binaries）；
  - 把 `CONFIG_XNU_OWNER_DATA_MOUNT` 关掉（payload 不需要 `--data-ramdisk`）；
  - 带一份 Apple 原始 static+system 信任缓存 bundle（61,356 B，sha256 `7416ca4f…`）；
  - `unixnu build payload` → `build firmware` → `uefi-fuxi/scripts/bootimage.py` 打 v3 头。

## 4. 还没解决的

- 显示驱动「编过」但**没在真机上跑过**：今晚这张 boot.img 是第一次上机。
- Adreno GPU kit 整条链还没进（XNU 版本错配，等对齐）。
- 设备仓库缺 `drivers/NativeHidInput`、`drivers/NativeKeyStoreEvents`，CI 里是临时 `git clone UniXNU/…` 补进去的。
- 想在 t50 上跑出真正的系统，还需要 `NativeUfs` 读 `/data` 里的 OS/SystemOS 窗口——那才涉及往 userdata 写 8.5 GB，今晚没动。

## 5. 复现

```
# 1) 内核
gh workflow run t50-kernel.yml -R chipppppppps/fuxi-t50 -f display=real
# 2) 打包（用上一步的 kernel artifact id）

# 3) 下载后自检
python tools\check_boot_img.py <boot.img>
python <repo>\ci\check-boot-image.py …   # UniXNU 线的检查器，t50 的 v3 头不适用
```
